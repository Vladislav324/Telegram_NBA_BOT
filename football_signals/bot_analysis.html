Реальная точность модели

Теоретическая точность Dixon-Coles
58–62%
По академическим исследованиям (Dixon & Coles, 1997 + обновления), модель с xG, формой и H2H предсказывает исход матча на 58–62% правильно. Случайное угадывание — 33%.
Точность с реальными коэффициентами
55–58%
При наличии острых линий (Pinnacle, Betfair) точность снижается из-за высокого bar для value. Зато ROI при edge ≥ 8% исторически ~5–12% на дистанции.
Точность расчётных коэф (сейчас)
Неизмерима
Когда модель сравнивает себя с собой — edge завышен, настоящего value нет. Сигналы правильные по направлению, но коэффициент нужен реальный для ставки.
Данных для валидации
~0
В demo_signals.csv — 303 записи, но без результатов матчей. Нельзя посчитать реальный % проходимости. Нужно накопить 200+ реальных исходов.

ML-обучение — дорожная карта

Фаза 1
Архитектура
Модель, пайплайн, API, сохранение сигналов в CSV. ✓ Готово
Фаза 2 ← сейчас
Накопление данных
Нужно: 200–300 исходов с реальными коэффициентами. При 3–5 матчах в день → 6–8 недель (с 1 апреля когда сбросится квота).
Фаза 3
Первое обучение
XGBoost/LogReg на: edge, market, league, day_of_week, team_form, xG_delta → predict win/loss.
Фаза 4
Интеграция
Модель корректирует min_edge по рынкам, отключает слабые факторы, настраивает Kelly-множитель.

Конкретный план запуска ML

Сейчас — март 2026
Запустить бот ежедневно, собирать сигналы
Каждый запуск пишет в signals.csv. Нужно добавить столбец с реальным результатом матча (W/L) — либо вручную, либо через автоматический check на следующий день.
1 апреля 2026
Квота Odds API сбрасывается → включаются реальные коэффициенты
С этого момента edge считается правильно. Данные до 1 апреля — только для модельной валидации направления.
Май–Июнь 2026 (~200 исходов)
Первое ML-обучение
sklearn LogisticRegression + XGBoostClassifier на накопленных данных. Цель: найти какие рынки/лиги/условия дают реальный edge, а какие — шум.
Конец 2026 (~1000+ исходов)
Полноценная ML-модель поверх Dixon-Coles
Neural net или gradient boosting, предсказывающий не просто исход, а реальную ценность ставки с учётом всех 17 факторов.

Что нужно сделать прямо сейчас

Критично
Реальные коэффициенты — без них edge не считается. 1 апреля: новый ключ Odds API. Или запустить с RU IP для Fonbet.
Критично
Добавить авто-верификацию результатов — бот должен на следующий день проверять матч (через football-data.org бесплатно) и записывать W/L в CSV. Без этого ML невозможен.
Важно
Статистика команд из реальных матчей — форма 1.00, Elo 1500 для многих команд = нет данных. Нужно донастроить загрузку через API-Football для текущего сезона.
Важно
Backtesting — прогон модели на исторических данных прошлого сезона. Покажет реальную точность до того как тратить деньги.
Улучшение
Азиатский гандикап — отключён сейчас, но даёт лучшие коэффициенты на одностороннем матче. Включить для матчей с большим перевесом (Elo разница > 200).
Итог: По архитектуре и факторам бот уже в топ-5% среди аналогов. Главное — это инструмент анализа, а не «гарантированный профит». Реальная эффективность подтвердится только после 200–300 задокументированных исходов с реальными коэффициентами. ML-обучение имеет смысл запускать не раньше мая 2026 при ежедневном использовании.
